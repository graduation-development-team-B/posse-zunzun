# 現在利用できる問題・回答形式

| 形式 | 入力 | 表示・採点 | 対象 |
|---|---|---|---|
| 選択式 | 単一選択・○× | 選択肢ID、誤答別の理由 | Web・Nativeの共通UI |
| 穴埋め・バグ診断 | 候補選択 | コードを表示して選択肢IDを判定 | Web・Nativeの共通UI |
| HTMLプレビュー | 1箇所をトークンで組み立て | iframe、教材用Tailwind固定サブセット、候補との一致。class順序は不問 | Web |
| JavaScript Console | 1箇所を候補で埋める | Workerで出力を取得し、構文の候補と期待出力を判定 | Web |
| Git・ターミナル・PR | トークンを組み立てて操作 | 宣言された操作列と模擬状態を確認 | Web・Nativeの共通UI |
| コード組み立て（実行なし） | 1箇所を複数のコード断片で埋める | 定義したトークン列との一致。class入力は順序不問、過不足は不正解 | Web・Nativeの共通UI |

移行後の394問（選択式・候補選択372問、HTML4問、Console8問、Git10問）を保持し、PH1・PH2に実行なしのコード組み立て135問、PH3 Week33〜48に80問を追加した。さらにPH3の各Weekへ4択10問、計160問を追加し、合計769問。PH3も既存の実行なし組み立てUIを使う。Native実機の動作確認は別途必要。

### 実行なしのコード組み立て

`assembly.language`に表示言語、`assembly.optionTokens`に候補IDごとの断片配列を記録する。各候補は2〜24断片で、結合した文字列をpayload.optionsのtextと一致させる。正答・主要誤答の断片を混ぜた候補欄から、必要なものを繰り返し選べる。候補欄は正答順をそのまま表示せず、問題IDに基づく安定した順に混ぜる。

通常は断片の順序・過不足を比較する。`assembly.inputMode="classes"`なら各断片を単一のclassとして扱い、順序を比較しない。候補以外の並びも不正解として確定でき、解説と模範コードを表示する。実行ボタン・実行結果・期待出力は付けない。画面には「コードの実行は行いません」と表示し、組み立てたコードを確認して確定する。自由なコードの意味を解析する採点器ではなく、設問ごとに用意した限定入力の採点である。

HTMLとConsoleは実行と回答確定を分ける。回答編集後の古い実行結果は確定に使えない。再起動後の未確定コードは再実行する。

HTMLの表示をReact Native要素で模擬して実行済みと扱わない。ConsoleのJSにはブラウザWorkerを使い、ログの件数・長さと実行時間を制限する。Gitは実PCや外部GitHubを操作しない。

複数選択、自由な任意コード、React/JSX実行、Tailwindの全機能、PHP・MySQL実行、サーバー採点、正答データの端末への非配信は未対応。これらが必要な問題はまず機能を実装・検証する。現行ローカル採点では正答が端末内のデータに含まれる。

全ての問題を毎回再実装する必要はない。対応済み形式を使う新Weekは、正本と単元設定の追加で出題できる。採点は単語やコードの完全一致を一般則にせず、今回の限定入力・学習目標に合う条件として扱う。

制作上の仕様とアプリに対応済みの機能は区別する。詳細な制作仕様はquestion-spec.mdを参照。
